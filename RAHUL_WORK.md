## Priority order (do in this order)

### 1. Judges must use it without help — in-app guided tour (scored: "usable without assistance")
Add a first-run guided tour (dismissible, re-openable from a "Help" button) that walks a judge through: pick a role → open CampusKart → ledger and a source chip → resolve a conflict → answer a gap question → approve and publish → switch to Successor → acknowledge. **Done when:** a new browser profile reaches "published, then acknowledged as Successor" by following only on-screen hints. Test it in a fresh/incognito window.

### 2. Cold-start and failure handling (the live API sleeps on Render)
In the HTTP layer and screens: show a clear "Waking the server, this can take up to a minute…" state; retry with back-off (about 6 tries over ~70 s) on network errors and 502/503/504; show a readable error with a Retry button on real failures (never a blank screen, never a raw stack trace). Add loading skeletons and empty states for every list (ledger, conflicts, gaps, sources, versions). Surface the job `error` field on the Reconstruct screen (the API reports partial model failures there).
**Done when:** with the API stopped, every screen shows a friendly error and recovers when it returns.

### 3. Export the approved handover (Round 3 improvement #3, can be done fully in the frontend)

**Done when:** the Contributor export contains no lead-only text (add this check to the permissions test).
