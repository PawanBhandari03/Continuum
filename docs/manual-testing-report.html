6. Suggested fixes (for Pawan; Rahul's side is listed too)

  1. Bulk approve. Add POST /handovers/{id}/claims/bulk with {action:"approve", state?:"verified", ids?:[...]}: one database write, one version bump, one audit row. The UI buttons "Approve all Verified" and "Approve all remaining" would call it (Rahul changes the client once it exists). Also worth checking why a single write takes 6 to 10 s (number of database round trips; Render and Supabase regions).
  2. Emit the project section (five-line summary) in the pipeline, or tell Rahul to hide empty sections.
  3. Merge conflicts that share a claim into one group; use the source's real date (commit or file timestamp), not the ingest date.
  4. Version numbers: bump once per publish or per batch, and keep a separate revision counter if needed.
  5. Version diff endpoint GET /handovers/{id}/versions/{a}/diff/{b} returning {added:[Claim], removed:[Claim], changed:[{claim_id, before, after}]}. The UI is ready and accepts before/after as text or partial claim.
  6. Look at the audit endpoint (35 s sample) and write latency in general.
  7. Rahul (done on branch rahul/web-upload-a11y, 33 local browser tests pass, axe finds 0 violations on 8 screens and 3 dialogs): parallel export fetching, larger tap targets, attention-first ordering, accessibility fixes, and a real file-upload UI for the Connect screen. Merging that branch into main redeploys the live site on Render, so Pawan decides when. Also: the GitHub token field on the Connect screen was never sent to the server; it is removed on the branch.
